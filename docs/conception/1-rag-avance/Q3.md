# Q3 — Dense, lexical, hybride, reranking

> **Question du brief.** « Pourquoi la recherche dense seule rate-t-elle "REF-8842" ? Que
> rattrape la recherche lexicale ? Comment combiner les deux (hybride), et qu'apporte un
> reranking en plus ? »
>
> Les chiffres de recherche de ce document viennent d'une **baseline BM25 écrite en Python
> pur** (30 lignes, aucune dépendance) et jouée sur les 30 questions transcrites en
> [description-corpus.md](description-corpus.md) §7. Script complet au §8. Ce document
> remplace `../docs/overview-rag.md` §Q3 ; les écarts sont au §7.

**Décision : BM25 + dense + RRF + rerank, et deux modèles multilingues — le corpus est
intégralement en français, les modèles cités par le premier jet sont anglais. La mesure
déplace par ailleurs le problème : sur les questions par référence exacte, le lexical seul
trouve déjà la bonne référence 8 fois sur 8. Ce qu'aucun étage de recherche ne tranche,
c'est *fiche technique ou notice* — et c'est ce que le test d'acceptance demande.**

## 1. Pourquoi le dense rate `REF-8842`

Un embedding encode du **sens**. `REF-8842` n'en porte aucun : le tokenizer le casse en
fragments (`REF`, `-`, `88`, `42`) dont aucun n'est discriminant. Toutes les références du
corpus se projettent dans la même région de l'espace — le voisinage encode « ceci est une
référence produit », pas « ceci est *cette* référence ».

Le corpus le montre crûment : `REF-8842` est un *disjoncteur tétrapolaire 40 A*,
`REF-8836` une *pince à sertir*. Deux produits sans rapport, deux chaînes quasi
indistinguables pour un vecteur. La brièveté de la requête aggrave tout : une question
réduite à une référence donne un vecteur presque vide de contenu.

**Un second effet, mesuré, et il est propre à ce corpus.** Les documents d'une même
collection partagent leur trame :

| Collection | Part du texte constituée de lignes présentes dans > 80 % des éditions |
|---|---:|
| `notices/` | **91 %** |
| `sav/` | 86 % |
| `fiches/` | 55 % |
| `notes/` | 18 % |

Neuf dixièmes du texte d'une notice sont la même phrase que dans les 79 autres, seules les
valeurs changent. Les 80 notices forment donc un peloton très serré dans l'espace
vectoriel : le dense y départage mal, non parce qu'il est mauvais, mais parce que **ce qui
distingue deux notices est justement ce qu'un embedding pondère le moins** — une référence,
une dimension, un nombre.

## 2. Ce que rattrape le lexical — et c'est plus que prévu

BM25 traite `REF-8842` comme un terme à IDF très élevé : après le nettoyage des liens
sortants décidé en [Q2](Q2.md) §2, il n'apparaît que dans 3 éditions courantes sur 350.

**Baseline BM25 seule, sur les 8 questions `reference_exacte` :**

| Critère de succès | Texte brut | Texte nettoyé (Q2) |
|---|---:|---:|
| **Hit@1**, la référence attendue est en tête (`attendu_reference`) | — | **8 / 8** |
| **Hit@1**, la *fiche technique* est en tête (test d'acceptance) | 0 / 8 | **2 / 8** |
| Hit@3, la fiche technique est dans les trois premiers | 3 / 8 | **8 / 8** |

Deux enseignements, et ils ne vont pas dans le même sens :

- **le nettoyage des liens sortants vaut à lui seul +5 en Hit@3.** La décision de Q2 n'était
  pas cosmétique : sur le texte brut, les fiches qui citent `REF-8842` en accessoire
  occupent le podium ;
- **le lexical suffit à trouver la bonne référence.** Sur le critère du jeu d'évaluation,
  BM25 seul est à 8/8 avant tout dense, tout RRF et tout rerank.

## 3. Ce que le lexical ne rattrape pas

C'est là que le dense gagne sa place, et les cas sont nommés — quatre trous lexicaux
identifiés en [description-corpus.md](description-corpus.md) §7.2, dont trois se vérifient
dans la baseline :

| # | Question | Ce que BM25 remonte | Nature du trou |
|---|---|---|---|
| 13 | précautions avant d'installer un produit électrique | — | **synonymie** : les notices disent « consignes de sécurité », le mot « précaution » n'existe nulle part |
| 09 | quel disjoncteur pour un départ moteur en triphasé ? | — | **flexion** : les fiches disent « départs moteurs » |
| 15 | quelle norme s'applique aux disjoncteurs modulaires | une **note interne** (4,8) | le mot « norme » est dans 57 fiches, mais dilué |
| 16 | garantie fabricant par défaut sur le catalogue | une procédure SAV (6,4) | **ambiguïté** : « garantie » est dans 93 fiches *et* 90 SAV |
| 19 | quel différentiel pour un circuit avec plaque de cuisson | une procédure SAV (5,9) | **absence** : « plaque de cuisson » n'existe dans aucun document |

**Onze questions `couverte` sur quatorze** remontent la bonne collection en tête avec BM25
seul. Les trois échecs sont exactement les cas où le mot de la question n'est pas le mot du
document — c'est la définition du travail que le dense fait et que le lexical ne peut pas
faire.

## 4. La fusion : RRF, et surtout pas une somme de scores

Les deux échelles sont incomparables. BM25 produit des valeurs non bornées, dépendantes de
la longueur de la requête et du corpus — **mesuré ici entre 1,1 et 19,0** sur les mêmes 22
questions ; le dense produit une similarité cosinus entre 0 et 1. Les additionner, même
pondérées, revient à choisir un taux de change arbitraire et à le recalibrer à chaque
changement de corpus.

RRF **jette les scores et ne garde que les rangs** :

```python
def rrf(listes, k=60):
    scores = collections.defaultdict(float)
    for liste in listes:
        for rang, edition_id in enumerate(liste, start=1):
            scores[edition_id] += 1 / (k + rang)
    return sorted(scores, key=scores.get, reverse=True)
```

Six lignes, aucune calibration. La décroissance est douce (rang 1 → 1/61, rang 2 → 1/62) :
un document **excellent dans une seule liste survit**, un document **moyen dans les deux
remonte**. C'est précisément le comportement voulu ici, où les deux listes ont des angles
morts complémentaires (§2 et §3).

**Les deux listes sont déjà filtrées par version** quand elles arrivent à la fusion — le
filtre s'applique avant la troncature de chacune, jamais après ([Q1](Q1.md) §5). Le rang
que RRF consomme est donc un rang parmi des éditions courantes, sans trou.

## 5. Ce qu'ajoute le rerank — et ce qu'il ne résoudra pas

Un cross-encoder lit la paire *(question, document)* **ensemble** au lieu de comparer deux
vecteurs calculés séparément. Il perçoit la correspondance de surface *et* le sens, et
c'est le seul étage capable de trancher les cas du §3 où le mot juste manque. Son score
sert une seconde fois, comme critère de refus ([Q4](Q4.md)).

**Ce qu'il ne tranchera pas, et il faut le dire avant de le mesurer.**

```
requête « REF-8842 »   (RAG-01, la question est la référence, nue)

BM25    1. notices/notice-REF-8842-v1.0.pdf   6,1     ← la notice cite la référence 2 fois
        2. notes/…-politique-tarifaire-01.md  5,5
        3. fiches/REF-8842-v2.1.pdf           4,5     ← la fiche la cite 1 fois
```

Le test d'acceptance exige que **la fiche technique** remonte en tête. Or rien, dans une
requête réduite à une référence, ne demande une fiche plutôt qu'une notice : les deux
documents *portent* cette référence et lui sont également pertinents. Un cross-encoder n'a
pas plus d'information que BM25 pour deviner l'intention — il ne peut pas inventer un
critère absent de la requête.

> **Décision : une règle de départage explicite, appliquée à la liste finale — à référence
> égale, `fiche_technique` passe devant `notice`.** Une fiche décrit le produit, une notice
> décrit son installation ; une question réduite à une référence demande le produit.

### La règle s'exprime en rangs, jamais en scores

> **Correction portée depuis l'audit de cohérence** ([../audit-coherence.md](../audit-coherence.md), S2).
> La première rédaction disait « à score équivalent » et « appliquée après le rerank ». Les
> deux formulations sont inapplicables telles quelles : [Q5](Q5.md) §1 exige que la règle
> soit appliquée **à l'identique dans les trois configurations comparées**, or la
> configuration B n'a pas de rerank, et [Q4](Q4.md) §3 a établi qu'un score BM25 n'a pas
> d'échelle — « scores voisins » n'y veut rien dire.

Le dossier a déjà tranché deux fois en faveur du rang contre le score : RRF jette les scores
(§4), et le filtre de version rend le rang interprétable ([Q1](Q1.md) §5). **Le départage
suit la même règle.**

```python
FENETRE = 3          # paramètre de configuration, publié avec la mesure

def departager(resultats):
    """Réordonne la liste finale. Aucune lecture du texte de la question."""
    tete = resultats[0]
    if not tete.reference or tete.doc_type == "fiche_technique":
        return resultats                      # rien à départager
    for i, r in enumerate(resultats[1:FENETRE], start=1):
        if r.reference == tete.reference and r.doc_type == "fiche_technique":
            return [r] + resultats[:i] + resultats[i + 1:]
    return resultats
```

Quatre propriétés, et ce sont elles qui rendent la règle défendable :

- **elle est sans dimension**, donc identique dans A, B et C. C'est la seule formulation qui
  satisfasse l'exigence de neutralité de [Q5](Q5.md) §1 ;
- **son déclencheur est une métadonnée de résultat, pas un motif dans la requête.** Elle ne
  lit jamais la question — donc ce n'est pas le routage par expression régulière refusé
  ci-dessus, et le Hit@1 continue de venir de la recherche. Un `if re.match(r"REF-\d{4}")`
  sur la question ferait venir le résultat de la règle, et E6 ne démontrerait plus rien ;
- **elle départage, elle ne classe pas** : un seul échange, borné à la fenêtre, entre deux
  documents portant la **même** référence. Sur la mesure du §5, la fiche de `REF-8842` est au
  rang 3 en BM25 seul : `FENETRE = 3` la couvre, et une fenêtre plus large exposerait
  davantage de questions en langage naturel à un réordonnancement non désiré ;
- **on publie les deux chiffres**, avec et sans la règle, et **sur les trois sous-ensembles**
  ([Q5](Q5.md) §3) — pas seulement sur `reference_exacte`. C'est sur `couverte` qu'elle peut
  nuire : une question dont l'`attendu_type` est `notice` verrait sa notice reculer d'un rang.
  Le publier est le seul moyen de le savoir, au lieu de le cacher dans un score.

## 6. Le choix des modèles : le corpus est en français

**Correction du premier jet, et c'est la plus lourde de ce chantier.**
`../docs/overview-rag.md` §Q3 arrête `ms-marco-MiniLM-L-6-v2` ; `all-MiniLM` est cité
ailleurs comme référence de fenêtre. **Les deux sont entraînés sur des corpus anglais** —
MS MARCO pour le premier. Or les 400 documents et les 30 questions sont en français, et le
reranker porte deux garanties à la fois : la barrière 1 du refus (E1) et l'arbitrage final
mesuré par E6.

| Étage | Retenu | Pourquoi | Repli si la mesure le demande |
|---|---|---|---|
| embedding | `intfloat/multilingual-e5-base` | multilingue, français dans l'entraînement, 512 tokens — le corpus tient à 45 % de la fenêtre ([Q2](Q2.md) §1) | `BAAI/bge-m3` (fenêtre 8192, plus lourd) · `Solon-embeddings` (français) |
| rerank | `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` | mMARCO = MS MARCO traduit, français inclus ; ~120 M de paramètres, tenable sur CPU pour 20 paires | `BAAI/bge-reranker-v2-m3` (meilleur, ~570 M — quelques secondes par requête sur CPU) |

**Un piège d'implémentation à ne pas découvrir en route :** les modèles E5 attendent des
préfixes — `query: ` devant la question, `passage: ` devant le document. Sans eux, les
vecteurs sont produits hors du régime d'entraînement du modèle et la qualité chute sans
qu'aucune erreur ne le signale. C'est le même mode d'échec que `statut = 'livrée'` côté SQL
(chantier 2, [Q1](../2-text-to-sql/Q1.md) §2) : syntaxiquement parfait, silencieusement
faux.

### Le coût réel : PyTorch revient par la porte du rerank

Le schéma affiche « pas de Docling ni de PyTorch » parmi ce que la sonde du corpus a
supprimé. **C'est vrai de l'ingestion, faux du projet** : un embedding local et un
cross-encoder s'exécutent tous deux sur PyTorch. L'arbitrage écarté à l'ingestion — ~2 Go
de dépendance contre une extraction robuste de tableaux, sans objet puisque le corpus n'a
aucun tableau — **n'est pas évitable au retrieval**, où le brief impose le reranking.

À écrire une fois, dans le schéma et dans le dossier : **PyTorch est une dépendance du
projet, apportée par le rerank, pas par l'ingestion.** Environ 2 Go d'installation, quelques
centaines de Mo de modèles téléchargés une fois, aucun appel réseau à l'usage, aucune donnée
du corpus qui sort.

**Et les trois versions se figent** — embedding, reranker, `pypdf` — au même titre et pour
la même raison : elles déterminent le contenu de l'index et le classement, donc la
comparabilité de la mesure E6 avant/après ([Q5](Q5.md)).

## 7. Ce que ce document corrige du premier jet

1. **deux modèles anglais sur un corpus français** — le point le plus lourd (§6) ;
2. **PyTorch n'est pas évité** : écarté à l'ingestion, il revient par le rerank ; le schéma
   dit le contraire (§6) ;
3. **le gain du lexical était supposé, il est mesuré** — et il est plus grand qu'annoncé sur
   le critère du jeu d'évaluation (8/8), plus petit sur celui du test d'acceptance (2/8) ;
4. **le tableau des rangs BM25/dense donné en exemple par le premier jet était illustratif** ;
   il est remplacé par une mesure réelle (§2, §5) ;
5. **le conflit fiche / notice n'était pas vu** : aucun étage de recherche ne le tranche, il
   faut une règle de départage explicite et publiée (§5).

## 8. Reproduction

La baseline BM25 tient en trente lignes sans dépendance autre que `pypdf`. Elle sert deux
fois : ici, et comme témoin lexical de la mesure E6 ([Q5](Q5.md)).

```python
import pathlib, re, math, collections
from pypdf import PdfReader

root = pathlib.Path("data/corpus")
def texte(p):
    if p.suffix == ".pdf":
        return "\n".join(pg.extract_text() or "" for pg in PdfReader(str(p)).pages)
    t = p.read_text(encoding="utf-8", errors="replace")
    return re.sub(r"<[^>]*>", "", t) if p.suffix == ".html" else t

def sans_liens(t):                      # Q2 §2 — les liens sortants ne sont pas indexes
    out = []
    for l in t.splitlines():
        if l.strip().startswith("Accessoires et produits associés"):
            continue
        if "exemple traité sur la référence" in l or "référence exacte (ex." in l:
            l = re.sub(r"REF-\d{4}", "", l)
        out.append(l)
    return "\n".join(out)

editions = {}
for p in sorted(root.rglob("*")):
    if not p.is_file() or p.name.startswith("."):
        continue
    rel = str(p.relative_to(root))
    m = re.search(r"-v(\d+\.\d+)\.", p.name)
    editions[rel] = {"v": m.group(1) if m else "1.0",
                     "cle": re.sub(r"-v\d+\.\d+(?=\.\w+$)", "", rel),
                     "texte": texte(p)}

courantes = {}                          # Q1 §7 — la version la plus haute par cle
for rel, d in editions.items():
    v = tuple(int(x) for x in d["v"].split("."))
    if d["cle"] not in courantes or v > courantes[d["cle"]][1]:
        courantes[d["cle"]] = (rel, v)

tok = lambda s: re.findall(r"[A-Za-zÀ-ÿ0-9]+(?:-\d+)?", s.lower())
D = {rel: tok(sans_liens(editions[rel]["texte"])) for rel, _ in courantes.values()}
df = collections.Counter()
for t in D.values():
    df.update(set(t))
N, avg = len(D), sum(len(t) for t in D.values()) / len(D)

def bm25(q, k1=1.5, b=0.75):
    scores = {}
    for rel, t in D.items():
        f, s = collections.Counter(t), 0.0
        for w in tok(q):
            if w in f:
                idf = math.log(1 + (N - df[w] + 0.5) / (df[w] + 0.5))
                s += idf * f[w] * (k1 + 1) / (f[w] + k1 * (1 - b + b * len(t) / avg))
        scores[rel] = s
    return sorted(scores.items(), key=lambda x: -x[1])

print(len(D), "editions courantes indexees")                 # -> 350
print(bm25("REF-8842")[:3])
# -> notice 6.1  ·  note politique-tarifaire 5.5  ·  fiche 4.5      (§5)
print(bm25("précautions avant d'installer un produit électrique")[0])
# -> aucun document ne contient le mot « précaution »              (§3)
```
